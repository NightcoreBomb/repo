# Задачі продукту (ЛР3, super loop)

Прошивка `firmware/App/app.c`, головний цикл — `app_poll()`. Усі часи — у тактах SysTick-лічильника
(`plat_cycles()`, 48 МГц; у Cortex-M0+ немає DWT, див. lab3-report.md §3.1).

## Головний цикл

```
main(): stack_paint → HAL_Init/RCC 48 МГц → MX_*_Init (регістри) → app_init → app_start (CHK, DIR)
while (1) app_poll():
    task_cmd   → task_btn → task_imu(+ctrl) → task_pot → task_rec | task_play → task_oled → task_telem
    [load N]   — штучна робота для пошуку точки зламу
    perf_load_poll
```

Кожна задача сама перевіряє «чи настав її час» (мітки часу, без черги подій) і повертається одразу,
якщо ні. Задачі виконуються до кінця — витіснення немає, тому найгірша затримка будь-якої задачі
дорівнює сумі найдовших тіл решти задач за один прохід (формула — lab3-report.md §3.3).

## Перелік задач

| Задача | Тригер | Період / подія | Дедлайн | Тіло (S1, avg / max) | FR |
|---|---|---|---|---|---|
| `task_imu` | час (такти) | 5 мс (200 Гц), `rate <hz>` змінює | наступний період (5 мс) | 2.02 / 2.17 мс | FR-01, FR-02 |
| `ctrl` (у `task_imu`) | новий відлік IMU | 5 мс | IMU → PWM ≤ 50 мс | 24 / 24 мкс | FR-03, FR-04, FR-05 |
| `task_pot` | час (мс) | 50 мс | 50 мс | 23 / 36 мкс | FR-04 |
| `task_btn` | прапорець debounce (SysTick 1 кГц) | подія | реакція — без числової вимоги в PRD (debounce 50 мс) | ≈ 10 / 54 мс (зміна режиму + `sd_write` dir) | FR-06 |
| `task_rec` | час (мс), лише REC | 20 мс (50 Гц) | інтервал ≤ 25 мс | 124 мкс / 14 мс (запис блоку 512 Б) | FR-07 |
| `task_play` | час (мс), лише PLAY | 20 мс | темп ±2 % | 156 мкс / 13.8 мс (читання блоку) | FR-08 |
| `task_oled` | час (мс) | 200 мс (5 Гц) | 200 мс | **62.8 мс** (режим 0) / 15.7 мс (1) / 3.2 мс (2) | FR-10 |
| `task_telem` | час (мс) | 100 мс, `telem <ms>` | — | 2.63 / 2.71 мс (блокувальний UART TX) | FR-11 |
| `task_cmd` | рядок у RX-кільці | подія | відповідь «без затримки» | 1.3 мс … 1.03 с (`calib`) | FR-11 |
| довгі операції | команда | `dump` (≈150 мс … 1.4 с), `calib` (≈1 с) | — (блокують цикл) | див. lab3-report.md §4 | FR-11 |

## Переривання

| Переривання | Пріоритет | Що робить | Навіщо |
|---|---|---|---|
| SysTick (1 кГц) | 3 (HAL) | `HAL_IncTick`, `app_tick_1ms` — опитування кнопки, лічильник debounce | часова база мс; рівномірне опитування кнопки |
| EXTI4_15 (PA8) | 3 | мітка тактів першого фронту після ≥ 60 мс тиші | вимір «перший фронт → реакція», якого не дає опитування |
| USART2 RX | 2 | байт → кільце 128 Б, мітка тактів кінця рядка, лічильники `dropped`/`ORE` | не губити байти, поки цикл зайнятий; вимір затримки команди |

Обробники не викликають драйверів шин і не друкують — лише прапорці, кільце і мітки часу.

## Службові піни (профіль аналізатора `lr3`, `tools/probe.py lr3`)

| Пін | Arduino | Сигнал | Значення |
|---|---|---|---|
| PA9 | D8 | P_IMU | 1 на час `task_imu` (ширина — час задачі, фронти — період) |
| PA10 | D2 | P_PWM | 1 на час оновлення CCR серво |
| PA15 | D7 | P_LONG | 1 на час довгої операції (`dump`, `calib`, запис/читання блоку SD) |
| PB3 | D3 | MARK | 1 на час реакції на кнопку (`task_btn`) |
