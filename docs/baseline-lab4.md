# Базова лінія для ЛР4 (super loop, ЛР3)

Мета документа: у ЛР4 (та сама плата, RTOS) повторити **ті самі сценарії тим самим інструментом**
і порівняти числа з таблицею §3. Вимірювальний код, формат логів і скрипти переносяться без змін;
змінюється лише те, що всередині `app_poll()`.

## 1. Як відтворити

Умови: Wokwi (Форма B), `diagram.json` з репозиторію, NUCLEO-C031C6 на 48 МГц, UART 115200 8N1,
I²C 100 кГц, SPI SD 6 МГц, прошивка з `make build` (у ЛР3 — `fw=126ed3cd`), вимірювальний код
увімкнено завжди (його вартість входить у числа).

```bash
make build                                 # firmware/build/firmware.hex
export WOKWI_CLI_TOKEN=...                 # https://wokwi.com/dashboard/ci
tools/run_lab3.sh                          # усі 13 сценаріїв ≈ 15 хв
tools/run_lab3.sh s3_worst event_longop    # вибрані
```

`run_lab3.sh` для кожного сценарію запускає `wokwi-cli --scenario tests/sim/lr3_<ім'я>.yaml
--serial-log-file docs/metrics/<ім'я>.log`, будує `tests/sim/diagram_noimu.json` (FR-12) і
`tests/sim/diagram_vcd.json` (аналізатор без SCL/TX), а наприкінці — `docs/metrics/results.md`
(`tools/lr3_metrics.py`) і `docs/metrics/vcd_btn.md` (`tools/lr3_vcd.py`).

Сценарії генерує `tools/lr3_gen_scenarios.py` (зерно `SEED=3` — випадкові моменти натискань однакові
в ЛР3 і ЛР4). **Не редагувати YAML вручну.**

Обмеження стенда: безкоштовний план Wokwi CI обриває прогін через 5 хв реального часу (≈ 120 с
симуляції цієї схеми), тому 6.2.6 триває 105 с, а не годину (lab3-report.md §4.5).

## 5. Вимірювальний інструментарій (без змін у ЛР4)

**Часова база.** `plat_cycles()` — 32-бітний лічильник тактів 48 МГц, складений із `uwTick` і
`SysTick->VAL` з перевіркою `COUNTFLAG`/`PENDSTSET` (на Cortex-M0+ немає DWT). Переповнюється раз на
89.5 с; різниця двох значень `uint32_t` коректна, доки інтервал < 89.5 с.

**Команди прошивки** (`help` виводить усі):

| Команда | Відповідь |
|---|---|
| `stats` / `stats reset` | блок `STAT BEGIN … STAT END` (нижче) / обнулити лічильники |
| `hist` | `HIST name=imu lt50=… lt100000=… lt4294967295=…` — гістограма інтервалів IMU (мкс) |
| `evt on/off` | події `EVT t_us=<такти/48> name=<…> [key=val]` |
| `note <тег>` | `NOTE <тег>` — розмітка логу для `lr3_metrics.py` (тег закінчується `;`) |
| `rate <hz>`, `load <us>`, `oled 0/1/2`, `telem <ms>` | параметри навантаження для 6.2.5 |
| `fault i2c 0/1` | емуляція затиснутої SDA у драйвері I²C (6.2.4) |
| `dump`, `calib` | довгі операції |
| `status`, `mode …`, `reset`, `selftest` | функції продукту / перезапуск / self-test ЛР2 |

**Формат блоку статистики** (рядки `key=value`, час у мкс):

```
STAT BEGIN fw=<хеш> t_ms= mode= oled_mode= telem_ms= imu_hz= load_us=
STAT name=<задача> n= min_us= avg_us= max_us=     # loop cmd btn imu pot rec play oled telem i2c_burst ctrl sd_write sd_read oled_txn uart_line long_op
LAT  name=<btn_db|btn_edge|cmd|imu2pwm> n= min_us= avg_us= max_us=
JIT  name=imu period_us= n= min_us= max_us= p99_us= missed=
LOAD last_pct= min_pct= max_pct= windows=
RX   bytes= dropped= ore=
I2C  recov= timeouts= imu_err= imu_samples=
REC  records= blocks= gaps= max_int_ms=
OLED frames= fps_x10=
MEM  stack_used= stack_size= ram_static= heap= first_imu_us=
STAT END
```

`LAT btn_edge` — від першого фронту кнопки (мітка в EXTI) до початку реакції; `btn_db` — від
підтвердження debounce до реакції; `cmd` — від символу кінця рядка (мітка в RX-перериванні) до
початку обробки; `imu2pwm` — від кінця читання IMU до запису CCR.

**Хост-скрипти.** `tools/lr3_gen_scenarios.py` (сценарії), `tools/run_lab3.sh` (прогін),
`tools/lr3_metrics.py <логи>` (таблиці Markdown), `tools/lr3_vcd.py <vcd>` (затримка кнопки,
P_IMU, P_LONG за аналізатором).

**Логічний аналізатор** (`wokwi-logic-analyzer`, профіль `tools/probe.py lr3`): D0 BTN (PA8), D1 P_IMU
(PA9), D2 P_PWM (PA10), D3 P_LONG (PA15), D4 PWM_PAN (PB4), D5 TX (PA2), D6 MARK (PB3), D7 SCL (PB8).
Для запису `lr3_btn_latency.vcd` D5 і D7 від'єднуються (`diagram_vcd.json`): інакше I²C за 20 с
дає 30 МБ, і Wokwi обриває запис. Роздільна здатність запису Wokwi — 1 нс, похибка вимірювання
визначається кроком симуляції (одиниці мкс).
