# PRD — Motion-Mirroring Teleoperator (Wokwi edition)

Основа: Проєкт 6 з Додатку A методички, адаптований під Форму B (Wokwi, NUCLEO-C031C6).

## A. Загальна ідея

Пристрій повторює нахил руки оператора на двовісній «віддаленій руці» з двох сервоприводів. IMU MPU-6050
кріпиться до кисті; мікроконтролер 200 разів на секунду обчислює pitch і roll комплементарним фільтром,
прибирає тремтіння (dead-zone + обмеження швидкості) і перетворює кути в положення серво pan/tilt.
Рухи можна записати на microSD і потім відтворити без оператора — так з «телеоператора» пристрій
стає автономним повторювачем траєкторії.

Для кого: навчальна модель систем телеприсутності (дистанційні маніпулятори, реабілітаційні тренажери,
motion capture). Цінність — замкнений real-time контур «сенсор → фільтр → актуатор» з вимірюваною
латентністю і персистентним журналом, тобто ті самі задачі, що й у промислових рішеннях, у мініатюрі.

Обмеження платформи: Cortex-M0+ без FPU, 12 КБ RAM — тому fusion робиться в мінімальному обсязі
(комплементарний фільтр, float у софті або fixed-point), а запис траєкторії — Δ-кодуванням.

## B. Функціональні вимоги

- **FR-01:** система повинна зчитувати акселерометр і гіроскоп MPU-6050 з частотою 200 Гц (±2 %).
- **FR-02:** система повинна обчислювати pitch і roll комплементарним фільтром з похибкою ≤ 3° у статиці відносно еталонного кута.
- **FR-03:** система повинна оновлювати PWM обох серво так, щоб латентність «зміна кута IMU → новий імпульс PWM» була ≤ 50 мс.
- **FR-04:** система повинна ігнорувати зміни кута менші за dead-zone; ширина dead-zone задається потенціометром у діапазоні 0–10°.
- **FR-05:** система повинна обмежувати кут серво діапазоном 0–180° (імпульс 500–2500 мкс) незалежно від вхідних даних.
- **FR-06:** система повинна перемикати режими Live → Record → Playback → Live коротким натисканням кнопки (debounce 50 мс).
- **FR-07:** у режимі Record система повинна записувати траєкторію на microSD з частотою ≥ 50 Гц, не менше 60 с.
- **FR-08:** у режимі Playback система повинна відтворювати записану траєкторію з тим самим темпом (розбіжність тривалості ≤ 2 %).
- **FR-09:** записана траєкторія повинна зберігатися після вимкнення живлення.
- **FR-10:** система повинна показувати на OLED поточний режим і кути pan/tilt з оновленням ≥ 5 Гц.
- **FR-11:** система повинна виводити по UART (115200 8N1) рядок телеметрії `t,pitch,roll,pan,tilt,mode` і приймати команди `mode`, `calib`, `status`.
- **FR-12:** при старті система повинна перевірити наявність MPU-6050 (WHO_AM_I = 0x68) і SD-карти; у разі помилки — повідомлення в UART і на OLED, серво в центр.

## C. Список датчиків і компонентів

| Компонент | Інтерфейс | Яку вимогу реалізує | Розглянуті альтернативи і чому відкинуті |
|---|---|---|---|
| **MPU-6050** (InvenSense) | I²C @0x68 | FR-01, FR-02, FR-03 — джерело орієнтації руки | **GY-89** (L3GD20+LSM303+BMP180) дає ще й магнітометр для абсолютного азимуту, але у Wokwi його немає, а 3 чипи на шині ускладнюють bring-up. **ADXL345** — тільки акселерометр, без гіро фільтр буде шумним при русі. |
| **Потенціометр 10 кОм** | ADC (PA0) | FR-04 — налаштування dead-zone «на льоту» | Налаштування через UART-команду — незручно під час демонстрації; енкодер KY-040 — ще 2 GPIO і обробка квадратури без реальної потреби. |
| **Кнопка** | GPIO + EXTI (PA8) | FR-06 — перемикання режимів | Тільки UART-команди — пристрій не можна використовувати автономно; ємнісна кнопка — немає в наборі. |
| **microSD** | SPI1 | FR-07, FR-08, FR-09 — журнал траєкторії | **W25Q64** (рекомендований методичкою) — ідентичний SPI-протокол, але відсутній у Wokwi; на Формі A замінюється без зміни архітектури. Внутрішня Flash МК — лише 32 КБ і вже зайнята прошивкою. |
| **SSD1306 OLED** | I²C @0x3C | FR-10, FR-12 — статус без ПК | LCD1602 по I²C — менше інформації на екрані; ILI9341 по SPI — надто «важкий» для 12 КБ RAM. |
| **2× серво SG90** (актуатори) | PWM TIM3 CH1/CH2 | FR-03, FR-05, FR-08 | Крокові двигуни — потрібні драйвери A4988 і більше пінів; для двох осей серво простіші й точніші в цьому діапазоні. |

Мінімум методички (3 компоненти з різними інтерфейсами) виконано: I²C (MPU-6050, OLED), ADC (потенціометр),
GPIO/EXTI (кнопка), SPI (microSD), PWM (серво).

## D. План тестування

| Вимога | Тест | Критерій проходження |
|---|---|---|
| FR-01 | Toggle GPIO (тестовий пін) на кожному читанні IMU; логічний аналізатор Wokwi → `.vcd` → PulseView, виміряти період | 5.00 мс ± 0.1 мс протягом 10 с |
| FR-02 | У Wokwi задати нахил MPU-6050 (повзунки accel) 0°, 30°, 45°, −30°; порівняти з виведеним pitch/roll | ≤ 3° у кожній точці |
| FR-03 | GPIO-мітка «нові дані IMU» і «оновлено CCR TIM3»; різниця фронтів на аналізаторі для 50 змін | максимум ≤ 50 мс |
| FR-04 | Потенціометр на 0 % і 100 %; дати повільний дрейф кута 0→5° | при 100 % серво не рухається, при 0 % рухається |
| FR-05 | Подати pitch = ±120° (через тестову команду UART) | імпульс PWM лишається в межах 500–2500 мкс |
| FR-06 | 20 натискань кнопки, у т.ч. серія з дрібним «брязкотом» | рівно 20 перемикань, порядок режимів правильний |
| FR-07 | Запис 60 с; прочитати файл через `sdcard/` директорію Wokwi | ≥ 3000 записів, без пропусків timestamp > 25 мс |
| FR-08 | Відтворити запис 60 с, виміряти тривалість по UART-мітках | 60 с ± 1.2 с |
| FR-09 | Записати 100 позицій, зупинити симуляцію (на залізі — вирвати живлення), запустити знову, відтворити | всі 100 читаються, CRC збігається |
| FR-10 | Змінити режим і кут, засікти оновлення OLED по аналізатору I²C (адреса 0x3C) | транзакції ≥ 5 разів/с |
| FR-11 | Надіслати `status`, `mode`, `calib` з Serial Monitor | коректна відповідь на кожну, телеметрія парситься Python-скриптом |
| FR-12 | Від'єднати MPU-6050 у `diagram.json` і запустити | повідомлення «IMU not found», серво 1500 мкс, без зависання |
